## 3. 踩坑与失败记录（史诗级排错复盘）
由于是零基础首次操作，今晚连续触发了 6 个经典报错，现逐一记录并复盘：

### ❌ 报错 1：命令拼写错误（手滑）
- **报错现场**：`git: 'swich' is not a git command.`
- **病因分析**：在创建分支时，把 `switch` 错打成了 `swich`。
- **解决处方**：根据系统提示的 `The most similar command is switch`，重新输入正确拼写。

### ❌ 报错 2：未正确授权（Gitee 安全机制拦截）
- **报错现场**：网页端提示“您的帐号安全评级较低，发布公开内容前请在「个人设置」完成2FA设置...”
- **病因分析**：新注册账号未绑定第三方账号，系统拒绝执行 Fork 操作。
- **解决处方**：在 Gitee 设置中绑定了第三方账号提升安全评级，成功解锁 Fork 权限。

### ❌ 报错 3：URL 路径包含中文（编码冲突）
- **报错现场**：`fatal: 'does not appear to be a git repository'`
- **病因分析**：设置远程仓库地址时，错误地将用户名写成了中文“史焰琪”，导致 Git 无法解析路径。
- **解决处方**：执行 `git remote set-url origin ...`，将路径修正为纯英文 `S111777333`。

### ❌ 报错 4：认证失败（密码与 Token 混淆）
- **报错现场**：`fatal: Authentication failed for 'https://gitee.com/...'`
- **病因分析**：Gitee 已停用账号登录密码作为 Git 密码，必须使用私人令牌。首次尝试输入了登录密码导致被拒。
- **解决处方**：前往 Gitee 设置生成私人令牌，并尝试使用该令牌。

### ❌ 报错 5：Token 格式携带非法字符
- **报错现场**：`remote: Incorrect username or password (access token)`
- **病因分析**：在使用 URL 直接传参的方法推代码时，误将占位符的尖括号 `< >` 一起复制到了 URL 中。
- **解决处方**：去掉尖括号，直接写为 `https://S111777333:令牌@gitee.com`。

### ❌ 报错 6：协议头拼写错误（少写字母）
- **报错现场**：`remote: Unauthorized`
- **病因分析**：将安全协议 `https://` 错打成了 `http://`（少了一个 `s`），Gitee 拒绝非安全协议认证。
- **解决处方**：补全 `s`，使用正确的 `https://` 协议头，最终成功推送。

## 4. 今日总结与反思
- **认知升级**：Git 容错率极低，一个字母的错误（如 `http` 少了 `s`）都会导致整个流程卡死。
- **安全意识**：彻底理解了私人令牌（Token）的作用，它替代了密码，且能通过权限勾选控制范围。
